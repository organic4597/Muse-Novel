# 기술 분석

## 요청 경계

모든 변경 요청은 인증, Origin, 본문 크기와 입력 스키마 검사를 통과한 뒤 Route Handler에서 처리됩니다. 프로젝트 하위 리소스는 URL의 projectId와 DB 소유 관계를 다시 확인합니다.

```text
React UI
  → 인증된 Next.js Route Handler
    → DB 트랜잭션 또는 서버측 외부 API 호출
      → JSON / SSE / AI SDK 스트림
```

## 스트리밍과 완성 판정

스토리 구상, 명령형 집필과 집필 에이전트는 모델 출력 조각을 브라우저에 즉시 전달합니다. 단순히 연결이 종료됐다는 이유로 완성으로 간주하지 않고 완료 이벤트와 파싱 결과를 확인합니다. 출력 한도나 타임아웃으로 잘린 설정·원고는 자동 적용하지 않습니다.

## 서버측 에이전트 루프

- 요청 해석과 필요한 자료 범위 결정
- 작품 기억·창작 지식 검색
- 필요 시 안전한 검색어 생성과 SearXNG 호출
- 장면 계획과 초안 작성
- 선택적 비평과 수정
- 사용자가 승인할 수 있는 결과로 반환

LLM은 계획 텍스트만 제안합니다. 도구 인자 검증, 루프 횟수, 취소, 저장 권한은 서버가 통제합니다.

## 성능 경계

- 대용량 캐릭터·챕터 목록은 렌더링 범위를 제한
- 편집기와 보조 패널은 동적 import
- 원고 직렬화는 worker 경로 사용
- 지도 포인터 이동은 animation frame으로 묶고 화면 밖 핀은 생략
- 웹 검색은 짧은 캐시와 동시 실행 제한
- 로컬 LLM은 기본 단일 슬롯 우선순위 대기열

## 데이터 일관성

지도 핀 배치는 revision을 포함한 전체 스냅샷으로 저장합니다. 설정 수정은 제안과 반영을 분리하고 현재 버전이 달라지면 거부합니다. 승인 직전 상태와 복원 직전 상태를 이력으로 남겨 다시 되돌릴 수 있습니다.

## 장애 처리

외부 API의 실패는 DB·원고 기능과 격리합니다. AbortSignal을 통해 브라우저 취소와 서버 제한 시간을 결합하고, 부분 출력은 완료 플래그가 없으면 적용 버튼을 잠급니다. 임베딩 장애는 키워드 검색으로 전환합니다.

구체적인 경로와 요청 형식은 [외부 API 계약](External-Services), 구성 개요는 [아키텍처](Architecture)를 참고하세요.
