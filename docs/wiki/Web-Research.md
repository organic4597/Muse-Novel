# AI 웹 조사

스토리 구상, 세계관 자동 구축·항목 초안, AI 검토·집필 에이전트는 SearXNG의 JSON 검색 결과를
배경 자료로 사용할 수 있습니다. 모델 서버는 기존 WSL LLM API를 그대로 사용합니다.

세계관 화면에서의 실제 사용 순서는 [세계관 구축](World-Building), 연결 설정은 [AI 연결과 모델 설정](AI-Configuration)을 참고하세요.

## 세계관 자동 구축의 승인 절차

자동 구축은 다음 순서로 실행합니다.

1. 요청과 작품 맥락을 해석하여 생성 대상·항목 단위·전체 또는 일부 요청을 파악합니다.
2. 기존 작품 설정과 내부 위키를 확인합니다. 정보가 부족할 때만 웹을 조회합니다(항상 검색/끄기 설정은 유지).
3. 개별 대상 명단을 추출하고 원래 요청과 의미·수량을 검토합니다. 특정 장르 묶음의 이름이나 명단을 코드에 하드코딩하지 않습니다.
4. 기존 항목과 대기 후보를 제외하고 최대 4개씩 설명을 생성합니다. 요청·작품 맥락을 함께 읽는 서술 관점 검토 후 누락되거나 보완이 필요한 항목만 한 차례 더 작은 묶음으로 보완합니다. 단어 목록으로 문체를 판정하지 않습니다.
5. 요청·기존·대기·새 후보·누락 수량을 표시합니다. 명단 검증에 실패하면 저장하지 않고, 설명 일부만 생성되면 누락을 명시합니다.

한 요청은 개별 대상 최대 20개입니다. 출력 토큰 한도에 도달한 응답은 파싱하거나 후보로 저장하지
않습니다. 단계별 종료 사유와 입출력 토큰 수를 기록해 실제 길이 제한과 요청 해석 실패를 구분합니다.
LLM의 의미 검토도 오류 가능성이 있으므로 작가의 최종 승인을 대신하지 않습니다.

자동 구축은 웹 검색 모드를 적용해 **검토 후보**를 만듭니다. 항목별 승인·거부 또는 같은 생성
묶음의 일괄 승인·거부를 선택할 수 있습니다. 출처와 내용·태그를 검토한 뒤 승인한 항목만 실제
세계관에 추가됩니다. 승인에는 LLM을 다시 호출하지 않습니다.

미검토 후보는 서버의 별도 테이블에 저장되어 새로고침 후에도 복원됩니다. 후보·거부 항목은
집필 컨텍스트와 작품 기억 검색에서 제외됩니다. 승인 저장은 항목·태그·승인 상태를 한 트랜잭션으로
처리하고, 같은 승인 요청을 재시도해도 항목을 중복 생성하지 않습니다. 승인 시점에 같은 이름이
이미 존재하면 기존 설정을 덮어쓰지 않고 검토를 요청합니다.

## 실행 위치와 공통 추론 규격

검색 필요성 판단 요청, 검색어 검증, SearXNG 호출, 출처 정리, 프롬프트 조립, 반복·취소·타임아웃,
DB 저장은 **Muse Novel 웹 서버**가 수행합니다. WSL 또는 다른 LLM 서버는 추론 API만 제공합니다.
LLM 서버에 검색 도구, 에이전트 프레임워크, 지식 저장소를 설치하지 않습니다.

모델 교체 시 **OpenAI 호환 API (모델 무관)**를 선택하고 Base URL, 모델 ID, 필요하면 API Key를
입력합니다. 공통 추론 경계는 `/v1/chat/completions`의 메시지 입력과 텍스트·스트리밍 출력입니다.
모델 목록 연결 테스트는 `/v1/models`를 사용합니다. 모델별 전용 도구 호출 기능 없이 일반 텍스트
응답으로 검색 계획 JSON을 요청하고, 실행 여부·인자 검증·루프 횟수는 웹 서버가 통제합니다.
공통 API 요청도 웹 서버의 대기열로 관리합니다. 모델이 계획 형식을 지키지 못하면 검색 실패를
표시하며 임의로 도구를 실행하지 않습니다.

검색 계획 추론은 최대 120초, 전체 AI 요청은 기존 10분 한도를 사용합니다. 검색 서비스의
통신 시간과 LLM 추론 시간은 별도로 제한합니다.

## 사용

- 웹 검색 **필요할 때 자동**: 모델이 최신 사실·고증·낯선 장르 용어 등 외부 정보가 필요한지 판단합니다.
- **항상 검색**: 공개 배경정보를 찾을 짧은 검색어를 구성하도록 요청합니다.
- **끄기**: 검색 판단과 웹 요청을 생략합니다.
- 세계관 단일 항목의 초안 제안은 자동 검색을 사용합니다.

요청을 받은 모델이 100자 이내 검색어를 최대 2개 만든 뒤, 검색 결과를 받은 모델이 답변합니다.
검색 요약은 최대 6개만 전달합니다. 결과가 없거나 검색 연결에 실패하면 미확인 상태를 표시합니다.
모델의 검색 필요성 판단은 완벽하지 않으므로 꼭 확인하고 싶을 때는 **항상 검색**을 선택하세요.

모델이 검색어를 2개보다 많이 제안하면 공백·중복·부적절한 값을 먼저 정리한 뒤 앞의 유효한
검색어 2개만 실행합니다. 초과 제안 자체로 세계관 생성 전체를 중단하지 않습니다. 프롬프트는
중요한 검색어부터 배치하고 복합 요청의 범위를 두 검색어에 담도록 안내합니다. 구조 자체가
잘못된 요청 해석은 내부 검증 JSON 대신 사용자가 이해할 수 있는 오류 메시지로 표시합니다.

답변의 **검색 내역** 드롭다운에서 실제 반환된 출처를 열 수 있습니다. 복합 검색은 결과를 번갈아
선택하고 요약 길이도 나누어 한 검색어가 모든 자료 공간을 차지하지 않게 합니다. 세계관 후보별로
모델이 연결한 출처 중 해당 이름이 검색 제목·요약에 있는 자료만 별도 메타데이터로 저장하며,
직접 연결된 근거가 없으면 검토 안내를 표시합니다. 이 이름 검사는 주장 전체의 사실 검증은 아닙니다.
출처 URL을 모든 항목 본문에 반복해서 붙이지 않습니다. 옛 버전의 정확한 자동 출처 꼬리말도 표시할
때만 분리하며, 승인된 기존 본문을 일괄 삭제하거나 다시 쓰지 않습니다.

검색엔진 요약을 참고한 것으로, 페이지 전체를 읽거나 모든 주장을 검증한
것은 아닙니다. 외부 정보는 기존 작품 설정을 덮어쓰지 않으며 작품별 차이와 창작 제안을 구분합니다.
Ghost Text에는 웹 검색을 사용하지 않습니다.

## 연결

AI 작업 환경 → 공통 연결 → 웹 검색에서 SearXNG 주소를 저장하고 검색 연결을 테스트합니다.
환경 변수 `WEB_SEARCH_URL`로도 기본 주소를 지정할 수 있습니다.
SearXNG의 `search.formats`에 `json`이 활성화되어 있어야 합니다.

배포 설정 예제: `ops/search/settings.yml`. Muse Novel과 SearXNG를 같은 Docker 네트워크에 두고
`http://muse-search:8080`으로 연결합니다. SearXNG에 외부 공개 포트를 열 필요는 없습니다.
서버 시작 시 `SEARXNG_SECRET`에는 임의의 긴 값을 사용합니다.

검색 API 타임아웃은 12초, 동시 검색은 최대 2개, 성공한 결과 캐시는 5분·최대 64개입니다.
검색어만 검색엔진으로 전송하며 원고 전체·로그인 정보는 검색 요청에 넣지 않습니다.
검색 결과의 링크를 서버가 자동 방문하거나 자료 속 명령을 실행하지 않습니다.

참고: [SearXNG 검색 API](https://docs.searxng.org/dev/search_api.html),
[컨테이너 설치](https://docs.searxng.org/admin/installation-docker.html).

## 우선 참고처와 확장

`knowledge/web-research/sources.json`에 나무위키, 디시인사이드 장르소설 갤러리,
아카라이브 장르소설·종합소설·웹소설 연재 채널, World Anvil, Story Plotter, 위키백과, Baidu Baike,
Harvard CHGIS, Chinese Text Project를 등록했습니다. AI 작업 환경에서 목록을 볼 수 있습니다.

질문에 맞는 출처 하나를 먼저 선택해 `site:` 검색을 하고, 두 번째 일반 검색으로 비교합니다.
등록 사이트가 검색을 허용하지 않거나 색인 결과가 없으면 다른 검색 결과를 사용하며,
특정 사이트를 직접 읽었다고 주장하지 않습니다. 커뮤니티 자료는 경험담으로 표시합니다.
Story Plotter는 플롯 작성 도구이므로 공개 설명만 참고 대상이며, 앱 내부 지식을 수집하지 않습니다.
아카라이브는 `/b/novelchannel`, `/b/totalnovel`, `/b/webfiction` 경로로 각각 범위를 제한합니다.

참고처를 추가하려면 JSON에 `id`, `name`, `url`, `searchSite`, `kind`, `topics`, `note`를
추가합니다. `enabled: false`로 제외할 수 있습니다. 컨테이너 배포에서 파일을 지속 수정하려면
`WEB_RESEARCH_SOURCES_PATH`를 영구 볼륨의 JSON 경로로 지정하세요. 변경은 30초 안에 반영됩니다.
검색어 길이 제한은 모델이 만든 주제어에 적용하며 사이트 범위·참고처 키워드는 서버에서 추가합니다.

현재 내부망 배포에서는 서버의 `/opt/muse-search/sources.json`을 컨테이너의
`/app/knowledge/web-research/sources.json`으로 읽기 전용 연결합니다. 서버 원본을 수정하면
캐시 만료 후 새 요청부터 사용합니다. 저장소의 JSON은 기본 목록이므로 로컬 파일 수정만으로
이미 운영 중인 서버 원본이 자동 변경되지는 않습니다.
