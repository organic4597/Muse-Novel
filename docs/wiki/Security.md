# 로그인과 운영 보안

Muse Novel은 한 명의 관리자가 사용하는 개인 작업실 구성을 기본으로 합니다. 인증 설정 후 `/api/health`와 인증 경로를 제외한 화면·API·업로드는 로그인 세션이 필요합니다.

## 최초 설정 코드

`MUSE_AUTH_SETUP_TOKEN`은 네트워크의 다른 사용자가 먼저 관리자 계정을 만드는 일을 막는 배포용 코드입니다. 로그인 비밀번호와 다른 값이며 사용자가 직접 생성합니다.

Linux, macOS, WSL:

```bash
openssl rand -hex 32
```

Windows PowerShell:

```powershell
[Convert]::ToHexString([Security.Cryptography.RandomNumberGenerator]::GetBytes(32)).ToLower()
```

출력된 값을 Git에 포함되지 않는 `.env.local` 또는 `.env`에 저장합니다.

```dotenv
MUSE_AUTH_SETUP_TOKEN=<생성한 64자리 값>
```

서버를 시작하고 `/setup`의 **초기 설정 코드**에 같은 값을 입력한 뒤 관리자 아이디와 12자 이상 비밀번호를 만듭니다. 코드가 설정되지 않으면 입력칸이 표시되지 않으므로 LAN 배포에서는 서버를 열기 전에 반드시 설정하세요.

계정 생성 뒤에는 환경 변수에서 코드를 제거하고 컨테이너를 다시 만들어도 됩니다. 이후 `/login`에서는 관리자 아이디와 비밀번호만 사용합니다.

## 비밀번호 저장

- 원문 비밀번호를 저장하거나 로그에 남기지 않음
- 자격 증명마다 32바이트 무작위 salt
- scrypt `N=2^17`, `r=8`, `p=1`, 64바이트 파생 키
- 일정 시간 비교
- 인증 디렉터리와 파일을 제한된 권한으로 생성

기본 인증 위치는 `data/auth`입니다. 이 디렉터리를 잃으면 기존 비밀번호와 세션을 복구할 수 없습니다. 인증만 초기화하려 해도 먼저 전체 데이터 디렉터리를 백업하세요.

## 세션과 요청 보호

- HMAC-SHA256 서명 세션, 로그인 후 24시간 만료
- 로그인·최초 설정·인증 처리·상태 확인을 제외한 모든 페이지, API, 업로드 파일은 유효한 로그인 세션 필요
- `HttpOnly`, `SameSite=Lax`, `Priority=High` 쿠키
- HTTPS에서는 `Secure` 자동 적용
- 로그아웃 시 session epoch를 올려 기존 세션 폐기
- 로그인 본문 크기·처리 시간 제한과 반복 실패 throttling
- 변경 요청의 Origin 프로토콜·호스트·포트 검증
- 업로드 경로에도 세션 검사

## 리버스 프록시

기본값은 전달 헤더를 신뢰하지 않습니다. TLS 리버스 프록시가 모든 전달 헤더를 직접 덮어쓰고 외부에서 위조할 수 없는 구성일 때만 `AUTH_TRUST_PROXY=1`을 사용하세요. 잘못 설정하면 Origin 검증 우회나 로그인 오류가 생길 수 있습니다.

## HTTP 주의

salt와 scrypt는 저장된 비밀번호를 보호하지만 네트워크 전송을 암호화하지 않습니다. HTTP는 신뢰할 수 있는 내부망에서만 사용하고 공유기 포트 포워딩으로 공개하지 마세요. 인터넷이나 공용 Wi-Fi에서는 TLS를 먼저 구성합니다.

## 비밀과 개인정보

- `.env`, DB, `data/auth`, 암호화 키와 업로드는 Git 제외
- 실제 LAN IP, 홈 디렉터리, 호스트명과 API 키를 문서에 기록하지 않음
- 공개된 키는 Git에서 파일을 지우는 것만으로 보호되지 않으므로 즉시 폐기·재발급
- 백업도 자격 증명과 원고가 포함된 민감 데이터로 취급
