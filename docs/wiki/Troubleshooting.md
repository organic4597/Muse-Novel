# 트러블슈팅

## ChatGPT 로그인을 시작하지 못함

오류가 `network_challenge`이고 **Cloudflare 보안 확인에 차단됨**으로 표시된다면 계정이나 기기 코드 설정 문제가 아닙니다. Muse Novel 운영 서버에서 `auth.openai.com` 요청이 `403`과 `cf-mitigated: challenge`를 받아 Codex가 기기 코드를 발급받지 못하는 상태입니다. API 키나 인증 캐시만 복사해도 실제 추론 경로가 함께 막힐 수 있으므로 해결되지 않습니다.

서버의 외부 IP·네트워크 경로를 변경하거나, Codex가 정상 동작하는 신뢰된 장비에 추론 전용 브리지를 두어야 합니다. 프록시를 사용한다면 인증정보를 가로채지 않는 신뢰 가능한 경로와 TLS 검증이 필요합니다. 인증 캐시를 임의로 업로드하거나 공개 저장소에 넣지 마세요. 기기 코드 자체가 비활성화된 경우에만 ChatGPT 보안 설정 또는 워크스페이스 관리 권한에서 device code login을 켭니다.
핀 배치·이동·색상·상태는 상단 **저장** 전까지 브라우저 초안입니다. 다른 지도 이동이나 새로고침 경고에서 변경 버리기를 선택했는지 확인하고, 필요하면 **저장된 핀 위치 불러오기**로 서버 저장본을 복원합니다.
## 첫 접속에서 초기 설정 코드를 요구함

`MUSE_AUTH_SETUP_TOKEN`을 서버 환경에 설정한 경우 `/setup`에 같은 값을 입력해야 합니다. 이 코드는 관리자 비밀번호가 아닙니다. `.env`를 바꾼 뒤 Docker 컨테이너를 다시 만들지 않았다면 이전 환경이 계속 사용될 수 있습니다.

입력칸이 보이지 않으면 환경 변수 값이 없거나 빈 값입니다. LAN 공개 전에 코드를 설정하고 재시작하세요.

## 로그인 화면으로 계속 돌아감

- `/app/data` 영구 볼륨이 이전 컨테이너와 같은지 확인
- `data/auth/credential.json`과 session secret의 읽기 권한 확인
- 브라우저 쿠키 차단 여부 확인
- 서버 시간을 확인
- 비밀번호는 복구할 수 없으므로 인증 초기화 전 데이터 디렉터리를 백업

## 허용되지 않은 요청 출처

브라우저 주소의 프로토콜·호스트·포트와 서버가 인식하는 주소가 달라서 발생합니다.

- 내부 주소와 프록시 주소를 섞어 접속하지 않기
- 리버스 프록시가 `Host`, `X-Forwarded-Proto`를 올바르게 덮어쓰는지 확인
- 신뢰된 프록시를 사용할 때만 `AUTH_TRUST_PROXY=1`
- 페이지를 연 주소와 API 요청 주소가 동일 origin인지 확인

## Local LLM 연결 실패

1. Muse Novel 서버가 실행되는 환경에서 `{baseUrl}/health` 호출
2. `{baseUrl}/v1/models`의 실제 ID 확인
3. Base URL에 중복 `/v1`이 붙지 않았는지 확인
4. Docker의 `127.0.0.1`이 호스트 LLM을 가리키지 않는다는 점 확인
5. 방화벽과 llama-server 바인딩 주소 확인

## AI 응답 시간이 초과됨

일반 장기 요청은 최대 10분입니다. 대기열에 앞선 작업이 있으면 대기 시간도 포함됩니다.

- 운영 진단에서 active/queued 확인
- 모델이 아직 로딩 중인지 LLM 로그 확인
- 지나치게 큰 context와 10만 토큰 KV cache 설정 점검
- 병렬 수를 무리하게 늘리지 말고 실제 tokens/sec 측정
- 출력 토큰 수와 요청 목표 길이 축소

## 스토리 구상 응답이 잘리거나 입력창이 잠김

최신 코드는 텍스트를 스트리밍하고 완료·오류 후 입력창을 다시 활성화합니다. 네트워크가 끊긴 경우 새로고침 후 브라우저에 저장된 draft를 확인하세요. 잘린 구조화 출력은 안전을 위해 적용하지 않습니다.

## Markdown 표가 깨짐

스토리 구상 응답은 GFM 표를 지원합니다. 구버전 배포인지 확인하고 강력 새로고침 후 다시 시도하세요. 모델이 열 수와 구분선을 다르게 출력한 잘못된 Markdown은 정상 표로 만들 수 없으므로 재요청합니다.

## World assistant 후보가 요청 수보다 적음

- 요청 해석 결과와 누락 수량 표시 확인
- 기존 확정 항목과 대기 후보가 중복 제외됐는지 확인
- 검색 결과가 실제 대상 명단을 포함하는지 드롭다운 확인
- 출력 한도 도달 시 해당 응답은 후보로 저장하지 않으므로 더 작은 묶음으로 재요청
- 한 요청의 개별 대상은 최대 20개

## 임베딩 연결 실패

집필은 키워드 검색으로 계속됩니다. `/v1/models`, 모델 ID, API 키와 pooling 설정을 확인한 뒤 기억 동기화를 다시 실행하세요. 모델이나 pooling이 바뀌면 revision 값을 바꿔 캐시를 무효화합니다.

## 이미지 생성 오류

- Diffusers `/health`, `/generate` 응답 확인
- Automatic1111 `/sdapi/v1/txt2img` 확인
- base64 이미지 배열이 반환되는지 확인
- CUDA·VRAM·모델·LoRA 오류는 외부 이미지 서버 로그에서 확인
- LoRA 선택이 보여도 외부 서버가 실제 적용 필드를 지원하는지 확인

## 지도 변경이 사라짐

핀 배치·이동·색상·상태는 상단 **저장** 전까지 브라우저 초안입니다. 다른 지도 이동이나 새로고침 경고에서 변경 버리기를 선택했는지 확인하고, 필요하면 **저장된 핀 위치 불러오기**로 서버 저장본을 복원합니다.
