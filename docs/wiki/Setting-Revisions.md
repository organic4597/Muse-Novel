# 기존 설정의 AI 수정과 복원

캐릭터 또는 세계관 항목의 상세 창에서 **AI로 수정 · 수정 이력**을 엽니다.
수정 요청을 입력하고 **수정안 생성**을 누른 뒤, 변경 전·후를 비교하여 원하는 필드만
선택하고 **선택한 수정 승인·저장**을 누릅니다. 생성·조회·반영하지 않기는 작품 설정을 변경하지 않습니다.

기본 검색 모드는 끄기이며 기존 항목과 내부 글쓰기 지식을 참고합니다. 고증이나 외부 정보가
필요하면 웹 검색을 선택할 수 있습니다. LLM은 공통 추론 API만 제공하고 검색·검증·저장·복원은
Muse Novel 서버에서 처리합니다. 모델이 출력 한도에 도달하면 잘린 수정안을 저장하지 않습니다.
긴 기존 필드를 조용히 자르지 않으며, 전체 전달 한도를 넘으면 일반 수정을 안내합니다.

## 기록하는 범위

- 캐릭터: 이름, 역할, 외모, 성격, 배경, 캐릭터 아크, 소지품
- 세계관: 제목, 카테고리, 본문, 본문에 연결된 출처 정보

일반 수정과 AI 승인 전에 해당 항목의 이전 기본 설정을 보관합니다. 이미지·태그·관계·다른 항목은
복원하거나 자동 수정하지 않습니다. 별도의 카테고리 일괄 이름 변경·삭제 작업 자체는 이력 대상이
아닙니다. AI가 본문을 변경할 때 출처도 이번 조회 기준으로 갱신하며, 조회하지 않았으면 오래된
출처를 새 내용의 검증 자료처럼 표시하지 않도록 연결을 해제합니다.

## 복원과 충돌 처리

이력의 **복원 내용 확인**으로 먼저 차이를 확인하고 **이 버전으로 복원**을 누릅니다.
복원 직전 상태도 새 이력으로 저장하므로 그 기록을 선택해 되돌릴 수 있습니다.
검토 이후 다른 화면에서 항목이 변경됐다면 승인을 거부하고 최신 내용으로 다시 검토하도록 안내합니다.
항목 업데이트와 이력 저장은 같은 SQLite 트랜잭션으로 처리됩니다.

과거 카테고리가 이후 이름 변경·삭제된 경우 현재 연결된 분류를 사용합니다. 복원으로 없어진
카테고리를 다시 만들지 않습니다. 이력은 기본 20개씩 조회하며 이전 이력을 더 불러올 수 있습니다.
기능 적용 이전에 이미 덮어쓴 내용은 소급 복구할 수 없습니다. 항목 자체나 작품을 삭제하면 그에
속한 이력도 함께 삭제됩니다. 이것은 삭제된 항목 복구나 전체 세계관의 자동 일관성 보장 기능은 아닙니다.

## 구현 경계

`/api/projects/[id]/entity-edits/[kind]/[entityId]`는 해당 작품·종류·항목에만 접근합니다.
GET은 현재 상태·이력 또는 복원 미리보기를 반환하고, POST의 `propose`는 저장 없는 수정안 생성,
`apply`와 `restore`는 버전 검증 후 명시적 승인 저장을 수행합니다. 허용된 필드 이외의 변경은
거부하며, 이력의 항목 ID·프로젝트·종류를 교차 검증합니다.
