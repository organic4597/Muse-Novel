# 시간축·복선 인과·회차 마감 구현 계획

## 범위

기존 상태 메모, 장면 계획, 세계관 항목, 원고 저장과 AI 요청 구조를 확장한다. LLM은 구조화 후보만 반환하고 검색·검증·승인·DB 반영은 웹 서버가 담당한다.

## 1. 작품 시간과 회차별 상태

1. 프로젝트 설정에 단일 작품 달력(연호, 월 수, 월별 일수, 시간 단위)을 저장한다.
2. 챕터에 작품 연·월·일·시간과 정확도(연/월/일/시간/상대/미정)를 연결한다.
3. 기존 상태 메모에 대상 세계관 항목, 종료 회차, 정보 소유자(실제/독자/인물), 확신 정도와 원고 근거를 추가한다.
4. 기준 회차 조회는 시작 회차가 기준 이전이고 종료 회차가 기준 이후인 기록만 현재 상태로 계산한다.
5. 집필 AI 문맥을 실제 사실, 시점 인물이 아는 정보, 독자 공개 정보로 구분한다.

## 2. 복선·사건 인과 보드

1. 프로젝트 메뉴에 `복선·인과` 페이지를 추가한다.
2. 사건/선택/결과/복선 심기/재언급/회수/정보 공개/상태 변화 노드를 세로 시간축에 배치한다.
3. 노드 사이에는 원인/가능/동기/방해/공개/회수 연결만 둔다.
4. 회차, 작품 날짜, 흐름 이름, 상태와 종류로 필터링한다.
5. AI 제안은 초안으로 저장하고 사용자가 확정해야 집필 문맥에 포함한다.

## 3. 이번 화 마감

1. 원고를 저장하고 본문 해시를 고정한다.
2. 현재 회차 원고와 관련 설정만 AI에 전달해 상태·지식·사건·복선 후보를 구조화한다.
3. 서버가 모든 근거 문장이 실제 원고에 한 번 이상 존재하는지 검증한다.
4. 후보별 승인/거부와 수정 후 승인을 제공한다.
5. 승인 시 상태 기록과 인과 노드를 하나의 마감 배치로 반영한다.
6. 동일한 원고 해시는 중복 반영하지 않는다.

## 커밋 경계

1. 데이터 기반과 작품 달력
2. 회차별 상태·지식 UI와 AI 문맥
3. 복선·사건 인과 보드
4. 이번 화 마감 후보 생성
5. 승인 반영과 집필 화면 통합
6. 문서·회귀 테스트·모바일 최적화

## 이번 구현에서 제외

- 여러 달력 사이의 자동 환산
- 윤달과 천문 시뮬레이션
- 자유 배치 그래프 캔버스
- 자동 승인과 원고 자동 수정

필요가 확인되면 기존 날짜와 노드 데이터를 유지한 채 확장한다.
