# 캐릭터 소속·직위 이력과 회차별 등장 항목 구현 계획

상태: 1차 구현 완료. 카테고리 특성, 캐릭터 소속·직위 이력, 회차별 등장 항목, 회차 범위 AI 문맥과 검색 필터가 구현되었다.

현재 구현 범위:

- 카테고리의 단체·장소/지형·물건 특성 편집.
- 복수 소속·대표 소속·직위와 초기/회차 시작/회차 종료 변화 기록.
- 기존 소속 기록 정정·삭제, 감사 이력과 낙관적 revision 검사.
- 집필 화면의 인물·장소/지형·물건·단체·기타 드롭다운.
- 직접 등장/언급만, 회차 메모와 독립 저장 revision.
- 현재 회차 시작 기준 소속과 등장 항목을 집필 AI 문맥에 반영.
- 미래 회차 본문·상태 메모를 의미/키워드 기억 검색 순위 계산 전에 제외.

후속 범위:

- 회차 재정렬 전 소속 영향 미리보기와 확인 토큰.
- 단체 상세의 소속 인물 역조회 UI, 전 회차 연결 복사와 지도 핀 바로가기.
- 페이지네이션 단체 검색, 원고에서 등장 후보 자동 추출·승인.
- 회상·평행 시간선·장면 내부 시점과 자유서술에 섞인 미래 정보 분석.

## 1. 목표와 합의된 범위

1. 캐릭터 정보에 `소속`과 `직위` 두 필드를 나란히 제공한다.
2. 소속 선택 대상은 **단체 특성이 있는 카테고리에 속한 세계관 항목**이다. 특성은 항목 태그와 별개다.
3. 캐릭터의 소속·직위 변화를 적용 회차와 함께 기록한다.
4. 집필 화면에서 회차별 등장인물·장소/지형·물건·단체를 작은 드롭다운으로 확인하고 편집한다.
5. 집필 AI가 현재 회차의 등장 항목과 당시 소속·직위를 참고한다.
6. 기존 데이터, 세계관 링크, 지도 핀, 원고 자동 저장과 수정 이력을 보존한다.

구현 세부와 후속 기준을 함께 기록한다. 운영 배포 전에는 신규 마이그레이션과 실제 데이터 복제 검증을 다시 수행한다.

## 2. 현재 코드에서 확인한 출발점

| 영역 | 현재 상태 | 구현 시 필요한 변경 |
| --- | --- | --- |
| 캐릭터 | `characters`에 이름·역할·배경·소지품 등이 있음 | 소속을 별도 관계와 회차별 이력으로 관리 |
| 카테고리 | `world_categories`: ID·이름·별칭 | ID에 특성을 연결하고 기본 가상 카테고리도 처리 |
| 세계관 항목 | `world_entries.category`는 이름 문자열 | 기존 별칭 해석을 유지하며 특성 조회에 사용 |
| 회차 | `chapters.id`와 `order`로 관리 | 번호 대신 ID를 참조하고 정렬 변경의 시간 영향 검토 |
| 상태 메모 | `story_state_entries`에 chapterId·이전 값·활성 여부 | 소속 원본 데이터와 중복 저장하지 않고 읽기 표시 재사용 |
| AI 문맥 | `build-story-context.ts`에서 활성 상태 메모를 읽음 | 회차 기준 소속 계산과 상태 메모의 시간 필터 추가 |
| 작품 기억 | `project-memory.ts`에서 전 회차와 현재 설정을 수집 | 회차 범위를 검색 전에 제한하고 최신 소속의 과거 유입 방지 |
| 설정 복원 | `entity-revisions`는 캐릭터/세계관 기본 필드 스냅샷 | 소속 이력 편집에 별도 버전 검사·감사 기록 필요 |

`characters.role`은 주인공·조연 등의 **서사 역할**이다. 소속 내 직위로 재사용하지 않는다.

## 3. 화면 구성

### 3.1 카테고리 특성

세계관 카테고리 편집창에 이름과 특성을 분리해 표시한다.

```text
카테고리 이름  [종파                 ]
카테고리 특성  [✓ 단체] [ 장소·지형] [ 물건]
```

- `organization` / 단체: 캐릭터 소속의 선택 대상.
- `location` / 장소·지형: 회차 표시줄의 장소·지형 기본 분류.
- `item` / 물건: 회차 표시줄의 물건 기본 분류.
- 특성이 없는 카테고리는 일반 세계관으로 유지한다.
- 카테고리에 여러 특성을 허용한다. 예: 조직이자 장소인 학원.
- 단체 여부는 이름이나 항목 태그의 키워드로 추측하지 않는다. 작가가 지정한다.
- 기존 기본 `장소`, `물건`은 첫 설정에서 대응 특성을 제안한다. 적용 전 미리보기에서 확인하며 사용자 카테고리는 자동 분류하지 않는다.

### 3.2 캐릭터 정보

```text
소속 [소림사 ▾]               직위 [명예장로           ]
대표 소속 ✓                  [+ 다른 소속 추가]

기준 회차 [8화 ▾]            [소속 이력 보기]
```

- 평상시에는 대표 소속 두 칸만 보이고, 겸직은 펼쳤을 때 표시한다.
- 소속은 세계관 항목 검색·선택, 직위는 자유 입력이다.
- 미지정은 `미설정`, 확인된 소속 없음은 `무소속`으로 구분한다.
- 직위 미입력은 허용한다. 이를 AI가 임의로 채우지 않는다.
- 클릭하면 기존 세계관 상세 창을 열고, 단체 상세에서는 해당 단체의 소속 인물을 역조회한다.
- 기준 회차가 없는 캐릭터 목록에는 `최종 등록 회차 기준`임을 표시한다. 미래로 지정한 승진 기록을 초기 상태처럼 보이지 않게 한다.
- 지도 핀에서 캐릭터를 볼 때도 가능하면 같은 컴포넌트를 재사용한다. 지도에는 회차 기준이 없으면 최종 상태 표시라는 라벨을 붙인다.

### 3.3 변경 기록과 오타 정정

소속/직위 변경 시 저장 의미를 명확히 구분한다.

| 작업 | 동작 |
| --- | --- |
| 이야기 속 변화 기록 | 적용 회차·적용 시점·변경 사유를 입력하여 새 사건 기록 생성 |
| 기존 기록 정정 | 잘못 입력한 이름·직위·기준 회차를 바로잡음. 새 이야기 사건으로 계산하지 않되 편집 전 값 보관 |

변화 입력창은 소속·직위, 적용 회차, `회차 시작부터 / 회차 종료 후`, 사유를 제공한다. 해당 회차를 읽는 AI가 무엇을 현재 상태로 받는지 미리 보여준다.

### 3.4 집필 화면의 소형 표시줄

```text
이번 화: [인물 4 ▾] [장소·지형 2 ▾] [물건 3 ▾] [단체 1 ▾] [기타 0 ▾] [+ 연결]
```

- 원고 위에 한 줄로 배치하고 기본적으로 접는다. 모바일에서는 가로 스크롤을 허용한다.
- 클릭으로 열기/닫기. 바깥 클릭·Esc 지원. 키보드로 항목 탐색과 선택 가능.
- 드롭다운에는 검색창, 선택 항목, `직접 등장 / 언급만`과 간단한 메모를 표시한다.
- 인물: 이름, 해당 회차 시작 시점의 소속/직위. 해당 회차 종료 후 변화가 있으면 별도 변화 배지.
- 장소·지형: 이름, 원래 카테고리, 사용 가능한 지도 핀으로 이동.
- 물건: 이름, 원래 카테고리. 소지자가 구조화되어 있지 않으면 소지자를 추정해서 표시하지 않는다.
- 항목 클릭은 기존 상세 팝업, 연결 해제는 이번 화 관계만 삭제.
- 기본 숫자는 고유 연결 수다. 한 항목을 두 그룹에 표시하더라도 전체 합계에서는 한 번만 센다.
- 회차에 연결된 항목이 없다고 AI가 등장인물 전원이 부재한다고 판단해서는 안 된다. `미등록` 상태로 전달한다.
- 전 회차 연결 복사 버튼은 선택적으로 제공한다. 복사 전 목록 확인이 필요하며 소속 변화 기록은 복사하지 않는다.

## 4. 회차와 시간의 의미

### 4.1 기본 계산 규칙

1차 구현에서는 연재 회차 순서를 시간 기준으로 사용한다. 회상·동시 사건을 포함한 독립된 이야기 달력은 후속 범위다.

유효 시점은 `(chapter.order, boundary)`로 계산한다. `chapter_start`가 `chapter_end`보다 앞선다. 챕터 제목이나 화면의 “8화” 문자열은 참조 키로 쓰지 않는다.

- 집필 중 기본 조회: 현재 회차 시작 시점.
- `8화 시작부터` 기록: 8화 집필의 현재 상태에 포함.
- `8화 종료 후` 기록: 8화 시작 상태에는 제외하고 9화부터 현재 상태로 사용.
- 회차가 지정된 변화는 이후 변경 기록이 나올 때까지 유지.
- 회차 안에서 승진 장면을 쓸 때는 현재 상태와 **이번 화 예정 변화**를 따로 보여준다. 커서가 장면 전/후인지 자동 판단하지 않는다.
- `초기 설정`은 첫 회차 이전부터 유효한 명시적 기준점.
- 이력 없음은 `미설정`, 빈 소속 목록을 가진 초기/변화 기록은 `무소속`.

### 4.2 기준 예시

| 기록 | 5화 시작 조회 | 8화 시작 조회 | 9화 시작 조회 | 15화 시작 조회 |
| --- | --- | --- | --- | --- |
| 초기 무소속 → 3화 시작 소림사 객원 | 소림사 / 객원 | 소림사 / 객원 | 아래 승진 반영 | 아래 겸직 반영 |
| 8화 종료 후 명예장로 승진 | 적용 전 | 현재: 객원, 예정: 명예장로 | 소림사 / 명예장로 | 소림사 / 명예장로 |
| 15화 시작 무림맹 특별 고문 겸직 | 적용 전 | 적용 전 | 적용 전 | 소림사 명예장로 + 무림맹 특별 고문 |

### 4.3 복수 소속과 대표 소속

각 변화 시점에는 그 시점 이후의 **전체 소속 목록**을 저장한다. 가령 겸직을 추가할 때 기존 소림사 소속을 포함한 상태에 무림맹을 추가한다. 탈퇴는 이후 스냅샷에서 해당 소속을 제외하며 앞선 기록은 남긴다.

- 하나의 스냅샷에서 같은 단체 중복 선택 금지.
- 소속이 있으면 대표 소속은 정확히 하나. 새 겸직 추가가 대표 소속을 자동 교체하지 않는다.
- 직위만 바뀌어도 새 변화 기록을 만들 수 있다.
- 동일 캐릭터·회차·시점에는 하나의 기록만 허용한다. 추가 변화는 같은 기록에 합치거나 정정한다.
- 과거 시점에 기록을 삽입하면 이후 기록과 대표 소속이 어떻게 달라지는지 미리보기한다. 이후 스냅샷을 자동 수정하지 않는다.

## 5. 제안 데이터 모델

### 5.1 카테고리 특성

`world_category_traits`

| 필드 | 의미 |
| --- | --- |
| categoryId | `world_categories.id` FK |
| trait | `organization / location / item` |

`UNIQUE(categoryId, trait)`. 카테고리 이름 변경은 ID와 특성을 보존한다. 카테고리 삭제 시 특성 행만 정리한다.

호환 원칙:

- 현재 `world_entries.category` 문자열을 한 번에 제거하지 않는다.
- 카테고리 이름과 별칭을 기존 resolver로 해석해 해당 ID의 특성을 조회한다.
- 기본 가상 카테고리에 특성을 지정할 때 먼저 DB 행을 생성하고 ID를 확보한다.
- 삭제된 카테고리의 별칭을 이동 대상에 합치는 기존 동작을 유지한다. 삭제된 카테고리의 단체 특성을 이동 대상 전체에 자동 전파하지 않는다.
- 항목 검색용 태그와 카테고리 특성의 UI·API·저장 위치를 구분한다.

### 5.2 소속 변화 기록

`character_affiliation_events`

| 필드 | 의미 |
| --- | --- |
| id, projectId, characterId | 식별자와 프로젝트 범위 |
| chapterId | 적용 회차 FK. 초기 설정/회차 삭제 시 null |
| boundary | `initial / chapter_start / chapter_end / unplaced` |
| chapterTitleSnapshot | 회차가 삭제되어도 기록 위치를 읽을 수 있는 표시용 값 |
| reason | 변화 또는 정정 이유 |
| createdAt, updatedAt | 편집 시간. 이야기 시점 계산에는 사용하지 않음 |

초기 설정은 캐릭터당 하나, 회차 시작/종료 기록은 각 시점당 하나라는 부분 유니크 인덱스와 서버 검증을 사용한다. `chapterId=null`만 보고 초기 상태로 해석하지 않는다. `unplaced`는 자동 시간 계산에서 제외한다.

`character_affiliation_members`

| 필드 | 의미 |
| --- | --- |
| id, eventId | 특정 변화 스냅샷에 속한 소속 행 |
| organizationEntryId | 세계관 단체 항목 FK, 대상 삭제 시 null |
| organizationTitleSnapshot | 삭제된 단체의 당시 이름 표시용 |
| position | 자유 입력 직위, 미입력 허용 |
| isPrimary | 해당 시점의 대표 소속 |

소속을 캐릭터의 단순 문자열 두 개로 저장하지 않는다. 두 UI 필드는 선택 시점 스냅샷을 편집하는 입력창이다. DB의 정규화 관계가 원본이고 카드용 요약은 조회 결과로 계산한다.

`character_affiliation_audits`: 변화 기록의 추가·정정·제거 전후를 기록하는 별도 편집 감사 이력. 사건 시점과 데이터 편집 시간을 혼동하지 않도록 분리한다. 기존 `entity-revisions` 필드 스키마에 관계 목록을 억지로 끼워 넣지 않는다.

동시 수정: `characters.affiliationRevision` 정수를 추가해 전체 타임라인에 낙관적 버전 검사를 적용한다. 과거 기록 변경·삭제도 revision을 증가시켜 최신 상태로 검토하게 한다.

### 5.3 회차별 등장 연결

`chapter_entity_references`

| 필드 | 의미 |
| --- | --- |
| id, projectId, chapterId | 식별자와 소속 회차 |
| characterId / worldEntryId | 둘 중 정확히 하나의 FK |
| presence | `appears / mentioned` |
| displayGroupOverride | 선택: 해당 회차의 표시 그룹, 기본 null |
| note, sortOrder | 짧은 메모와 그룹 내 표시 순서 |
| createdAt, updatedAt | 편집 시간 |

- 인물과 세계관 참조를 FK 없는 `targetType/targetId` 문자열 조합으로만 저장하지 않는다.
- DB CHECK로 대상 XOR를 검증하고 `(chapterId, characterId)`, `(chapterId, worldEntryId)`에 부분 유니크 인덱스를 둔다.
- 카테고리 특성이 하나면 기본 그룹을 결정한다. 복수 특성은 선택창에서 이번 화 표시 그룹을 고르고, 모호한 기존 연결은 `기타`로 보존해 정리를 안내한다.
- `displayGroupOverride`는 항목의 본래 카테고리나 특성을 변경하지 않는다.
- 지도 이미지 자체는 단체/물건과 다른 리소스다. 1차에서는 장소 세계관 항목에 연결된 기존 지도 핀으로 이동하고, 지도 이미지만의 직접 회차 등록은 후속으로 둔다.
- `characters.itemsJson`의 개인 소지품 텍스트를 임의로 공용 세계관 물건으로 변환하지 않는다. 회차 물건 연결은 세계관 물건 항목을 사용한다.
- 회차별 목록 동시 편집용 `chapters.referencesRevision`을 추가한다. 원고 content 저장 revision과 분리해 불필요한 충돌을 피한다.

### 5.4 인덱스와 범위 검증

소속 조회: `(projectId, characterId, chapterId)`, 역조회: `(organizationEntryId, eventId)`, 회차 목록: `(projectId, chapterId, sortOrder)`.

프로젝트·캐릭터·단체·회차가 모두 같은 작품인지 서버에서 검증한다. 입력된 FK가 실제로 존재하는 것만으로 충분하다고 보지 않는다. 가능하면 복합 키 제약으로도 보강한다.

## 6. 이름 변경·삭제·순서 변경 규칙

| 상황 | 처리 |
| --- | --- |
| 카테고리 이름 변경 | 특성과 기존 소속 연결 유지, 화면 표시 갱신 |
| 단체 특성 해제 | 새 소속 선택에서 제외. 기존 연결은 보존하고 특성 불일치 표시 |
| 단체 항목을 다른 분류로 이동 | 기존 소속 자동 삭제 없음. 새 선택 가능 여부 재계산 |
| 단체 항목 삭제 | 영향받는 인물 수와 이력 미리보기. 승인 후 FK null과 이름 스냅샷 보존, 연결 끊김 표시 |
| 캐릭터 삭제 | 그 인물의 소속 기록과 회차 연결을 연관 데이터로 정리. 다른 인물·단체 유지 |
| 회차 삭제 | 해당 회차 등장 연결 제거. 소속 사건은 `unplaced`로 보존하고 회차 재지정 안내 |
| 프로젝트 삭제 | 프로젝트 소유 소속·참조·감사 기록 모두 정리. 기존 삭제 순서/FK와 함께 테스트 |
| 회차 순서 변경 | 새 순서에서 전후 상태 미리보기. 영향이 있으면 확인 후 트랜잭션으로 반영 |

회차 정렬은 `chapterId` 연결을 유지하지만 상태 계산 결과는 달라질 수 있다. 앞 회차로 옮긴 승진, 겸직 목록 덮어쓰기처럼 의미가 바뀐 캐릭터를 표시한다. 회차 재정렬이 원고상 사건 순서를 옮긴다는 가정은 UI에 설명한다.

## 7. API 제안

모든 경로는 기존 세션·Origin 보호를 사용한다. 생성/수정과 조회를 분리하고 읽기 요청은 원본을 변경하지 않는다.

| 경로 | 용도 |
| --- | --- |
| `GET /api/projects/[id]/world-categories` 확장 | 카테고리 ID·이름·별칭·특성 반환 |
| `PATCH /api/projects/[id]/world-categories/[categoryId]/traits` | 특성 편집, 영향 미리보기/확인 |
| `GET /api/projects/[id]/affiliation-options?q=...&cursor=...` | 단체 특성 항목 검색, 페이지 단위 반환 |
| `GET /api/projects/[id]/characters/[characterId]/affiliations?atChapterId=...&boundary=start` | 기준 시점 소속 + 사건 이력 + revision |
| `POST /api/projects/[id]/characters/[characterId]/affiliations` | 적용 시점과 전체 소속 목록으로 변화 기록 추가 |
| `PATCH/DELETE .../affiliations/[eventId]` | 기록 정정/제거, revision 검사·감사 기록 |
| `GET /api/projects/[id]/world-entries/[entryId]/members?atChapterId=...` | 단체의 해당 시점 소속 인물 |
| `GET /api/projects/[id]/chapters/[chapterId]/references` | 연결 목록·분류별 개수·revision |
| `PUT /api/projects/[id]/chapters/[chapterId]/references` | diff 저장 또는 제한된 전체 목록 교체, revision 검사 |
| 기존 회차 reorder/delete API 확장 | 영향을 받는 소속 사건 미리보기와 확인 토큰 |

소속 저장 입력 예시:

```json
{
  "expectedRevision": 3,
  "chapterId": "chapter-id",
  "boundary": "chapter_end",
  "reason": "장로회의 승인",
  "memberships": [
    { "organizationEntryId": "world-entry-id", "position": "명예장로", "isPrimary": true }
  ]
}
```

중복 전송은 idempotency key로 새 사건을 중복 생성하지 않게 한다. 409 충돌 시 입력 초안을 유지하며 최신 상태 재검토를 안내한다. 회차 삭제/순서 변경 영향 미리보기 토큰은 대상 revision에 묶어 미리보기 이후 변경을 검출한다.

## 8. AI 문맥과 작품 기억 연결

### 8.1 공통 조회기

서버에 `getChapterWritingContext(projectId, chapterId, boundary)`를 두고 집필 에이전트·명령 편집·일관성 검사·향후 Ghost Text가 같은 계산 규칙을 사용한다.

우선순위:

1. 해당 회차에서 작가가 직접 연결한 등장 항목.
2. 등장인물의 해당 시점 소속·직위와 유효한 구조화 상태.
3. 현재 장면 요청·원고와 관련된 추가 설정.
4. 이전 회차 요약과 창작 지식.

등장 항목 등록은 검색 우선순위이며 전역 참조를 완전히 차단하는 화이트리스트는 아니다. 단, `언급만`으로 등록된 인물은 장면 참여자로 자동 추가하지 않도록 구분해 전달한다.

### 8.2 미래 정보 유입 방지

`project-memory.ts`는 현재 전체 챕터·상태 메모를 검색 자료로 수집하므로 UI 추가만으로 회차별 일관성이 해결되지 않는다.

- 새 소속은 현재 캐릭터 자유서술 본문에 최신 값만 복제하지 않고 구조화 조회로 주입한다.
- 회차·소속 사건·상태 메모 검색 결과에 출처 ID와 유효 시점 메타데이터를 붙인다.
- 의미 검색과 키워드 검색 모두 **검색 순위 계산 전에** 회차 범위를 적용한다.
- 기존 벡터 캐시에 유효 범위가 없으면 회차 제한 요청에서 사용하지 않고 재인덱싱하거나 유효 출처의 키워드 조회로 fallback한다.
- 현재 회차의 요약·개요와 이번 화 종료 후 변화는 장면 계획 자료로 따로 전달한다. 현재 확정 상태와 합쳐 쓰지 않는다.
- 현재 회차를 모르는 요청에는 임의의 최신 상태를 과거 시점으로 표시하지 않는다.
- 전체 작품 검사는 전체 시간선을 볼 수 있지만, 집필용 검색 모드와 명시적으로 분리한다.
- 조회 캐시 키에 프로젝트·회차 ID·시점·회차 순서 revision·소속 revision·회차 참조 revision을 반영한다.

1차 보장 범위는 구조화된 소속과 회차가 지정된 자료의 시간 필터다. 기존 자유서술 배경·작가 노트에 섞인 미래 정보까지 자동 추출·정정하는 것은 보장하지 않으며, 이 제한을 사용 문서에 명시한다. 모든 미래 정보 방지를 단순 프롬프트 지시로 해결했다고 간주하지 않는다.

### 8.3 기존 지속 상태 메모와 관계

소속 변화의 원본은 전용 소속 이력이다. 상태 메모 패널에는 링크된 읽기 전용 요약을 표시할 수 있지만 같은 값의 별도 정전 행을 자동 생성하지 않는다.

기존 자유 텍스트 메모에 소속이 있으면 작가가 확인해 이력으로 옮기는 보조 동작만 제공한다. 자동 마이그레이션으로 임의의 회차·단체를 확정하지 않는다. 구조화 소속과 자유 메모가 충돌하면 둘을 보여주고 정정을 요청한다.

## 9. 사용성·성능

- 드롭다운을 닫아도 작업 중 입력 초안을 보존한다.
- 표시줄의 개수/선택 목록은 회차 진입 시 경량 API 한 번으로 조회한다.
- 단체 선택 목록과 긴 이력은 커서 페이지네이션, 검색은 짧은 debounce와 이전 요청 취소를 사용한다.
- 인물별 소속을 N번 조회하지 않고 해당 회차 등장인물 ID를 묶어 조회한다.
- 회차 전환 시 이전 요청을 취소하고 응답의 chapterId를 검사해 다른 회차에 잘못 표시하지 않는다.
- 참조 목록 저장은 원고 자동 저장과 독립 상태 표시·재시도를 가진다.
- 반복 조회/화면 열기에는 LLM을 호출하지 않는다. 단체 특성 지정·소속 편집·등장 연결은 일반 DB 작업이다.
- 후보 자동 추출은 후속 단계이며 명시적 실행·검토·승인을 거친다.

## 10. 마이그레이션과 기존 데이터

1. 구현 시점의 최신 `drizzle` migration 번호와 스키마를 확인한다. 이미 배포된 migration은 수정하지 않는다.
2. 새 테이블과 revision 필드를 추가한다. 기존 캐릭터의 소속은 `미설정`으로 시작하며 AI가 보충하지 않는다.
3. 특성 설정에 필요한 카테고리 ID를 확보한다. 이름·별칭 충돌을 검사하고 unresolved 항목은 기존 상태로 보존해 안내한다.
4. 기존 원고·캐릭터·세계관·지도 핀 수와 링크, 사용자 태그가 그대로인지 검증한다.
5. SQLite와 선택 지원 중인 DB provider의 트랜잭션·FK 차이를 확인한다. SQLite 동기 쿼리를 클라우드에서 지원한다고 검증 없이 문서화하지 않는다.
6. 기능별 feature flag로 UI 노출을 순차적으로 연다. 새 테이블이 없는 구버전 서버와 연결되는 상황에서 프론트엔드 오류가 무한 반복되지 않게 한다.

## 11. 작업 순서와 완료 조건

| 단계 | 주요 작업 | 완료 기준 |
| --- | --- | --- |
| A. 기반 설계·마이그레이션 | 특성·소속 사건·회차 참조·revision·감사 이력 | 기존 데이터 보존, FK·범위·동시 수정 테스트 통과 |
| B. 카테고리 특성 | 편집 UI·단체 검색·별칭 처리 | 단체 선택이 특성 기준으로만 동작 |
| C. 캐릭터 소속 | 두 필드·복수/대표 소속·시점 이력·역조회 | 과거/현재 회차 조회와 정정·탈퇴·겸직 동작 |
| D. 회차 표시줄 | 그룹별 드롭다운·등장/언급·링크·복사 | 작은 화면에서도 원고를 방해하지 않고 저장/복구 가능 |
| E. AI 시간 범위 | 공통 조회기·검색 필터·캐시·인덱스 | 미래 승진 정보가 이전 회차 구조화 문맥에 들어가지 않음 |
| F. 회귀·배포 | 순서/삭제 경계·통합·E2E·사용 문서 | 운영 복제 데이터 검증 후 develop → main → release |

각 단계는 앞 단계가 동작하는 작은 단위로 커밋한다. A~D만으로 UI 사용은 가능하지만 E가 완료되기 전에는 'AI가 회차별 소속을 정확히 참조한다'고 표시하지 않는다.

## 12. 필수 테스트 시나리오

### 데이터와 시간 계산

- 미설정과 무소속을 구분한다.
- 3화 시작 가입·8화 종료 승진·15화 시작 겸직 예시의 모든 경계를 검증한다.
- 직위만 변경, 탈퇴, 재가입, 대표 소속 전환을 검증한다.
- 동일 회차/시점 중복 기록과 같은 단체 중복 선택을 거부한다.
- 과거 기록 삽입·정정과 회차 재정렬 이후 계산이 결정적이다.
- 회차 삭제로 chapterId가 null이 되어도 초기 소속으로 잘못 적용되지 않는다.
- 단체 특성 제거·이름 변경·카테고리 병합 후 기존 연결을 보존한다.
- 교차 프로젝트 연결을 거부하고 저장 중 실패 시 원본과 감사 이력이 함께 롤백된다.

### UI와 API

- 소속은 적격 단체만 검색되고 직위는 자유 입력이다.
- 회차 전환을 빠르게 반복해도 다른 회차의 선택 목록/소속이 섞이지 않는다.
- 연결 해제는 원본 항목이나 다른 회차 연결을 삭제하지 않는다.
- 드롭다운 클릭·키보드·Esc·모바일 스크롤이 정상 동작한다.
- 원고 저장 실패와 참조 목록 저장 실패를 별도로 표시한다.
- 저장 재시도와 다중 탭 편집에서 중복 사건이나 조용한 덮어쓰기가 없다.

### AI와 검색

- 5화 요청에 8화 종료 승진을 현재 직위로 주입하지 않는다.
- 최신 상태가 캐시에 있어도 과거 회차 요청은 과거 값을 받는다.
- 의미/키워드 검색 모두 같은 시간 제한을 지킨다.
- 미래 내용이 포함된 구버전 벡터를 회차 제한 요청에 재사용하지 않는다.
- `언급만`과 `직접 등장`이 프롬프트에서도 구분된다.
- LLM이나 임베딩이 중단되어도 수동 소속·등장 항목 편집은 정상 동작한다.

## 13. 1차에서 제외할 기능

- 장면·문단·커서 위치별 소속 변화 자동 판정.
- 회상·평행 시간선·달력을 포함하는 별도 서사 시간 모델.
- 원고에서 소속 변경과 등장 목록을 자동 확정하는 기능.
- 소지품 등장만으로 소유권·수량을 갱신하는 기능.
- 단체 간 외교·세력 관계 그래프와 비밀 신분별 시야 권한.
- 과거 캐릭터 이름·단체 명칭까지 모든 엔티티 필드의 시간별 복원.

추후 위 기능을 추가할 수 있도록 관계는 ID로, 시점은 명시적으로 저장하되 1차 UI는 소속/직위와 회차 드롭다운에 집중한다.
