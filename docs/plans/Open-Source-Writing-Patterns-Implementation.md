# 오픈소스 집필 패턴 적용 계획

기준일: 2026-09-07

## 목표

Muse Novel의 자동완성, 장면 생성, 장기 기억과 설정 변경을 하나의 불투명한 AI 호출로 처리하지 않는다. Continue·Tabby의 자동완성 역할 분리, KoboldAI의 문맥 계층, NarraLume의 후보 승인, novel-studio의 정전 승격 구조를 현재 서버 중심 아키텍처에 맞게 단계적으로 적용한다.

## 단계

### 1. Ghost 제공자와 실행 계약 분리

- 프로젝트별 Ghost 전용 제공자 설정을 추가한다.
- 전용 설정이 없으면 기존 Story 제공자를 상속한다.
- 같은 URL·모델을 가리켜도 설정과 health는 역할별로 표시한다.
- 로컬 Instruct 모델은 Chat Completions와 정식 chat template를 사용한다.
- 자동·명시적 제안 timeout을 분리하고 busy·timeout을 구분한다.
- 기존 프로젝트는 별도 조작 없이 Story 제공자를 계속 상속한다.

### 2. 자동완성 후보와 측정

- 자동 Ghost는 짧고 보수적인 한 후보만 요청한다.
- 명시적 재생성은 최대 3개 후보를 순차 탐색하고 이전 후보를 즉시 전환한다.
- Tab 전체 수락, 단어 수락, 폐기, timeout을 원문 없이 집계한다.
- 프로젝트별 수락률에 따라 debounce와 자동 제안 길이를 조절할 수 있는 기반을 만든다.

### 3. 명시적 양방향 채우기

- 자동 Ghost와 별도로 현재 선택 영역 또는 커서 앞뒤를 채우는 기능을 제공한다.
- 결과는 2~3개 후보 카드로 보여주고 삽입·재생성·폐기를 지원한다.
- 중간 채우기 결과는 사용자가 승인하기 전 원고에 반영하지 않는다.

### 4. 장면 이어쓰기와 설계 분리

- Auto, Guided, Tone/Style Shift를 별도 모드로 제공한다.
- 장면 비트, 회차 개요, 이번 화 등장 항목과 현재 상태를 표시 가능한 문맥 칩으로 제공한다.
- 장면 결과는 후보·계획·사용 문맥·검토 내용을 함께 보관한다.

### 5. 개요와 정전 영향 후보

- 원고 변경 뒤 챕터 개요, 인물 상태, 소속, 소지품, 관계, 복선에 영향을 주는 변경 후보를 만든다.
- AI 제안은 diff로 표시하고 승인·거부·복원을 지원한다.
- 승인된 사실만 장기 기억과 다음 회차 문맥에 들어간다.

### 6. 장편 설계 계약

- 작품 → 아크 → 회차 → 장면의 목표·갈등·전환·결과·훅을 구조화한다.
- 인물의 지식 범위와 POV 공개 범위를 구분한다.
- 계획을 확정한 뒤 집필하고, 검토를 통과한 결과만 정전으로 승격한다.
- 중단된 작업은 체크포인트에서 재개한다.

## 이번 구현 범위

이번 기능 커밋에서는 1단계를 완성하고 2단계의 요청 상태·후보 전환 기반을 마련한다. 이후 단계는 저장 형식과 승인 UI를 재사용해 별도 기능 커밋으로 진행한다.

## 진행 현황

- 1단계 완료: 프로젝트별 Ghost 전용 제공자, Story 상속, 역할별 health, 자동·명시 요청 timeout 분리
- 2단계 진행 중: 자동 요청은 단일 후보를 유지하고, 명시 재생성 후보는 문맥별 최근 3개까지 즉시 순환 가능
- 2단계 완료: 원문을 저장하지 않는 브라우저 집계와 수락률 기반 자동 제안 debounce 조정

## 완료 조건

- Ghost override의 생성·수정·삭제와 암호화된 키 보존이 동작한다.
- override가 없으면 프로젝트 Story → 공통 Story 순서로 기존 동작을 유지한다.
- Ghost route가 선택된 전용 provider와 model ID를 사용한다.
- 자동 요청과 명시적 요청이 서로 다른 timeout을 사용한다.
- busy, timeout, empty, success 상태를 클라이언트가 구분할 수 있다.
- 관련 API·쿼리·UI·프롬프트 회귀 테스트와 프로덕션 빌드가 통과한다.
